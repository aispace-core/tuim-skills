# My Web Design

`my-web-design` 负责把一个模糊的页面需求整理成可落地的 Web 设计方案。

它关注的不只是“好看”，而是同时处理：
- 信息层级
- 布局结构
- 视觉系统
- 交互节奏
- 工程可实现性

## 何时使用

当用户有下列需求时触发：
- 做官网、落地页、专题页、活动页
- 优化现有页面的视觉与信息结构
- 给一个产品或功能设计前端界面
- 需要风格提案、模块拆解或页面骨架

典型触发语：
- `帮我设计一个 SaaS 官网`
- `把这个页面做得更高级一点`
- `做一个产品落地页`
- `给这个后台首页重新排版`

## 不要使用

以下情况不优先使用本技能：
- 用户只要后端接口或数据库设计
- 用户只想做简单文案润色，不涉及页面
- 用户明确要原生 App 界面而不是 Web 页面

## 工作流

1. 先判断页面目标、目标用户与核心转化动作
2. 拆出页面的信息层级和关键模块
3. 选择匹配目标的视觉方向和版式策略
4. 定义配色、排版、间距、组件语义和交互重点
5. 输出可直接交给前端实现的页面说明

## 输出要求

- 优先给出页面结构，而不是直接堆装饰
- 明确首屏、主体内容、转化区和收尾区
- 说明为什么采用该视觉方向，而不只是描述样式
- 如果需求模糊，先给 2-3 个差异化方向供用户选
- 当用户要求代码时，再补 HTML/CSS/React 等实现方案

## 默认输出结构

1. 页面目标与受众判断
2. 信息架构与模块分区
3. 视觉方向与设计原则
4. 关键区块说明
5. 实现建议与注意事项

## 风格要求

- 避免廉价堆砌感和无意义渐变
- 保持层级清晰、主次明确
- 兼顾美观与工程落地
- 优先解释设计决策背后的原因
